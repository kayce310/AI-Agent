## Core Architecture

1. **Software Company as Multi-Agent System** — products/managers/architects/PMs/engineers as roles
2. **SOP-driven**: `Code = SOP(Team)` — Materializes Standard Operating Procedures for LLM teams
3. **MGX**: Natural language programming product — world's first AI agent development team
4. **Research**: SPO, AOT papers; AFlow accepted at ICLR 2025 (oral, top 1.8%)

## Key Innovation vs Kato

| Aspect | MetaGPT | Kato (current) |
|--------|---------|----------------|
| Philosophy | `Code = SOP(Team)` — software company simulation | Single agent for task execution |
| Roles | Multiple (PM/Architect/Engineer/PM) | Single (Kato assistant) |
| Input | Single-line requirement → full product output | Step-by-step CLI |
| MGX | Natural language programming team | N/A |
| Research | ICLR papers on agentic workflows | None |

## What Kato Should Borrow

1. **Role-based agent simulation** — MetaGPT shows coding as collaborative team effort. Kato could simulate multi-expert review
2. **SOP-driven workflows** — Standard Operating Procedures as code is powerful; Kato's prompt builder could embed SOP-like patterns
3. **MGX approach** — Natural language → multi-agent development team could inspire Kato's self-architecting behavior

## Applicability to Kato

- **High**: SOP-driven workflow design, role-based agent patterns
- **Medium**: Multi-expert review, code generation as team output
- **Low**: Full software company simulation (overkill for Kato)
