## Tóm tắt vấn đề

v5.0 đang ở phase "prompt engineering nâng cao", chưa phải "skill-based execution". Prompt builder 8 tầng là cải tiến so với monolithic template, nhưng vẫn là prompt, không phải skill.

---

## 1. Ma trận 5 Layer vs v5.0

| Layer | v5.0 | Gap |
|---|---|---|
| **Intent Layer** — "Mục tiêu cần đạt" | ⚡ Có `task` field trong `EngineRequest`. Nhưng không có intent schema chuẩn, không có "định nghĩa thành công" rõ ràng. | Thiếu `IntentSchema`: bài toán, tiêu chuẩn đúng/sai, phạm vi xử lý. |
| **Knowledge Layer** — "Tri thức để hành động" | ⚡ Có `knowledge/wiki/`, `knowledge/blueprints/`, `knowledge/raw/`. Nhưng không có `domain knowledge`, `business rules`, `style guide` riêng cho từng skill. | Tri thức tồn tại nhưng không được đóng gói theo skill. |
| **Execution Layer** — "Cách thực thi" | ❌ Chỉ có `tools.ts` (function definitions) + `engine.ts` (ReAct loop). | Cần: `scripts/`, `templates/`, `workflows/` đi kèm mỗi skill. |
| **Verification Layer** — "Kiểm chứng trước khi xong" | ❌ **Không có.** evolution.ts chỉ ghi lỗi sau khi fail, không prevent. | Layer quan trọng nhất bị missing hoàn toàn. |
| **Evolution Layer** — "Học từ lỗi" | ⚡ `evolution.ts` vừa được xây: error registry + adaptive rules + routing advice. | Mới ở mức tracking errors, chưa feedback vào skill design. |

**Điểm trung bình: 3.5/10** — Execution và Verification là 2 điểm mù lớn nhất.

## 3. 4 Nguyên tắc vàng bị vi phạm

| Nguyên tắc | v5.0 | Gap |
|---|---|---|
| 1. Một skill = một nhiệm vụ duy nhất | ❌ `tools.ts` có multi-purpose tools | Cần break tools.ts thành single-purpose skills |
| 2. Skill là folder, không phải 1 file | ❌ `knowledge/wiki/skills/` là file .md riêng lẻ | Mỗi skill cần: SKILL.md + templates/ + examples/ + verification/ + assets/ + changelog.md |
| 3. Luôn có verification đi kèm | ❌ `process()` không có step verify output | Cần inject verification step vào cuối ReAct loop |
| 4. Cấu trúc tốt hơn kiểm soát cứng | ⚡ `prompt-builder.ts` đã thiết kế workflow steps | Nhưng step verify còn trống, chưa có gate |

## 5. Root Cause

v5.0 architect theo hướng **"generic orchestrator"**: engine.ts là vòng lặp vạn năng nhận request → LLM → tool → response. Không có khái niệm "skill" như một first-class entity.

**Hệ quả:**
1. Tính tái sử dụng ≈ 0: Mỗi request là 1 lần LLM tự suy nghĩ lại từ đầu
2. Không có verification: Không có gate nào kiểm tra output trước khi gửi
3. Không có knowledge đóng gói: Tri thức nằm rải rác trong wiki, không gắn với skill nào
4. Evolution mới chỉ ở mức model routing: Chưa feedback vào skill design

## 6. Lộ trình nâng cấp đề xuất

### Giai đoạn 1 — Foundation (1 tuần)
```
src/core/skill-system/
  skill-manager.ts      # Quản lý vòng đời skill (register/load/evolve)
  skill-executor.ts     # Execute 1 skill: load context → run script → verify
  skill-registry.ts     # Index tất cả skills từ folder/
```
```
knowledge/skills/       # Thay thế knowledge/wiki/skills/ (flat .md)
  write-proposal/
    SKILL.md            # Intent + Knowledge + Execution
    templates/
    examples/
    verification/checklist.md
    changelog.md
```

### Giai đoạn 2 — Verification + Evolution (1-2 tuần)
- Thêm **Verification Layer** vào cuối `process()` pipeline
- Mỗi tool call output được verify bởi `verify-skill` trước khi return
- Auto-generate gotchas từ evolution error registry

## 7. So sánh autoskills (midudev) — Tham khảo

> **Lưu ý**: autoskills đã được clone về `knowledge/references/autoskills/` để tham khảo

autoskills có cách tiếp cận "skill = file" thay vì "skill = folder":
- Mỗi skill là 1 file configuration trong skills-registry
- Có manifest index.json với SHA-256 verification
- Security check layer trước khi install
- Agent folder mapping (Cursor, Claude Code, etc.)
- Lockfile (skills-lock.json) cho reproducibility

**Bài học từ autoskills cho v5.0:**
- ✅ Registry pattern cho skill discovery
- ✅ Cơ chế security/verification trước khi execute
- ✅ Cấu trúc skill files có tổ chức
- ❌ Nhưng thiếu templates/, examples/, verification/ — giống v5.0 hiện tại
